# Архитектурная спецификация и системное описание проекта SCreator

**Проект**: SCreator (Десктопное приложение для составления школьного расписания)  
**Роль**: Отечественный аналог aSc TimeTables для общеобразовательных школ, лицеев, гимназий и колледжей  
**Дата фиксации**: Сентябрь 2026 г.

---

## 1. Миссия и назначение продукта

SCreator — автономное настольное программное обеспечение для автоматизированного и ручного составления учебных расписаний в российских общеобразовательных учреждениях, лицеях, гимназиях и колледжах.

Продукт проектируется как современная отечественная альтернатива отраслевому стандарту aSc TimeTables со следующими ключевыми требованиями:
- **Эргономичный UI/UX:** отказ от перегруженных модальных лабиринтов устаревших Windows-приложений в пользу чистого пошагового мастера с адаптивными таблицами и интерактивными матрицами.
- **Автономность и безопасность:** локальное хранение проекта в файле `.scproj` (SQLite), отсутствие обязательного облака и защита персональных данных учителей и учеников.
- **Российская образовательная специфика:** поддержка сменности (1 и 2 смены), гибкого деления классов на подгруппы (языки, труд/технология, информатика, профили), объединенных уроков (физкультура, потоковые лекции) и персональных метод-дней учителей.
- **Разделение слоев:** быстрый реактивный графический интерфейс изолирован от вычислительно сложного фонового ядра дискретной оптимизации (Google OR-Tools CP-SAT).

| Слой системы | Выбранная технология | Инженерное обоснование |
|---|---|---|
| **Оболочка десктопа** | **Tauri 2.0 (Rust)** | Безопасность памяти, минимальный размер дистрибутива (~15 МБ), потребление ОЗУ < 40 МБ, нативные диалоги ОС. |
| **Интерфейс (UI)** | **React 19 + TypeScript** | Строгая статическая типизация всех сущностей, предотвращение ошибок `undefined`, высокая скорость рендеринга таблиц и сеток. |
| **Стилизация и компоненты** | **Tailwind CSS + Lucide Icons** | Адаптивная вёрстка без громоздких внешних UI-библиотек, полный контроль геометрии таблиц и адаптивности. |
| **Управление состоянием** | **Zustand (с Persist Middleware)** | Легковесный менеджер состояния с атомарными срезами (slices) и автоматической синхронизацией в локальное хранилище / `.scproj`. |
| **Файловый формат** | **Локальный SQLite в файле `.scproj`** | Стандарт надежности (ACID-транзакции, защита от повреждения при сбое питания, простота резервного копирования). |
| **Движок оптимизации** | **Google OR-Tools (CP-SAT)** | Промышленный решатель задач удовлетворения ограничений (Constraint Satisfaction), работающий в отдельном фоновом потоке. |

## 3. Реляционная модель данных и связи сущностей

В основе системы лежит строгая доменная модель. Вся информация об учебном процессе раскладывается на независимые справочники, которые сходятся в узловой сущности — **«Урок / Учебная нагрузка» (Lesson Requirement)**.

```
                  ┌──────────────────────┐
                  │    SchoolSettings    │
                  │   (Дни, Звонки)      │
                  └──────────┬───────────┘
                             │
         ┌───────────────────┼───────────────────┐
         ▼                   ▼                   ▼
  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
  │   Subjects   │    │  Classrooms  │    │   Teachers   │
  │  (Предметы)  │    │  (Кабинеты)  │    │  (Учителя)   │
  └──────┬───────┘    └──────┬───────┘    └──────┬───────┘
         │                   │                   │
         │                   │ ┌─────────────────┘
         │                   │ │ (Домашний каб.)
         │                   ▼ ▼
         │            ┌──────────────┐
         │            │   Classes    │
         │            │   (Классы)   │
         │            └──────┬───────┘
         │                   │ (1:N)
         │                   ▼
         │            ┌──────────────┐
         │            │  Subgroups   │
         │            │  (Подгруппы) │
         │            └──────┬───────┘
         │                   │
         └───────────┬───────┴───────────────────┐
                     ▼                           ▼
        ┌─────────────────────────┐   ┌─────────────────────┐
        │    Lesson Requirement   │   │     Constraints     │
        │  (Учебная нагрузка)     │   │    (Ограничения)    │
        │ - SubjectId             │   │ - Max gaps (окна)   │
        │ - TeacherIds[]          │   │ - Max lessons/day   │
        │ - TargetGroupIds[]      │   │ - Time-Off Matrix   │
        │ - AllowedRoomIds[]      │   └──────────┬──────────┘
        │ - HoursPerWeek          │              │
        │ - SlotLength (1/2)      │              │
        └────────────┬────────────┘              │
                     │                           │
                     ▼                           ▼
        ┌───────────────────────────────────────────────────┐
        │        Timetable Board / Placement Engine         │
        │                                                   │
        │  ScheduledCard:                                   │
        │  [ Day, Slot, LessonId, RoomId, TeacherId, Class] │
        └───────────────────────────────────────────────────┘
```

### Детальное описание доменных сущностей

#### 1. `SchoolSettings` & `TimeSlot` (Параметры и сетка звонков)
- Глобальные настройки учебного периода (название школы, учебный год, пятидневка/шестидневка, лимит уроков в день до 10).
- Массив слотов `TimeSlot`: точное время начала, окончания каждого урока и длительность перемены с поддержкой автоматического пересчёта расписания звонков.

#### 2. `Subjects` (Справочник дисциплин)
- Наименование, краткий код (для плашки в сетке), цветовой маркер, разрешение спаренных уроков (`allowDoubleLessons`).
- Персональная матрица ограничений доступности `timeGrid` (дни и уроки, когда предмет запрещен или нежелателен).

#### 3. `Classrooms` (Фонд помещений)
- Номер/название аудитории, корпус (`building`), вместимость (`capacity`), тип (`roomType`: обычный, компьютерный класс, спортзал, лаборатория, мастерская, актовый зал).
- Флаг `isShared` (совместный режим для размещения нескольких групп одновременно) и индивидуальная сетка `timeGrid`.

#### 4. `Teachers` (Педагогический состав)
- Полное ФИО, краткое имя (`shortName`), недельная норма нагрузки в часах (`contractHours`), телефон, email, закрепленный домашний кабинет (`defaultRoomId`).
- Индивидуальная матрица `timeGrid` (фиксация метод-дней, совместительства и недоступных слотов).

#### 5. `Classes` & `Subgroups` (Классы и подгруппы — Шаг 5)
- Параллель (1..11), литера («А», «Б»), сменность (1/2 смена), закрепленный кабинет класса.
- Структура подгрупп: деление на 2 группы (языки/информатика), гендерное деление (мальчики/девочки для технологии) и профили.

#### 6. `Lessons` (Учебная нагрузка — Шаг 6)
- Узловая сущность, связывающая: Предмет + Учитель (или группа со-преподавателей) + Класс (или подгруппа, или объединение классов) + Допустимые кабинеты + Количество часов в неделю + Тип слота (одиночный урок или пара).

#### 7. `Constraints` (Диспетчер ограничений — Шаг 7)
- **Жёсткие правила (Hard):** отсутствие пересечений у одного учителя, класса и кабинета; соблюдение матриц Time-Off.
- **Мягкие правила (Soft):** минимизация окон у педагогов, равномерное распределение предметов по дням недели, соблюдение баланса суточной нагрузки.

#### 8. `Timetable Board` (Доска расписания — Шаг 8)
- Интерактивная доска с тремя проекциями: «По классам», «По учителям», «По кабинетам».
- Drag-and-drop карточек уроков с подсветкой доступных слотов и мгновенной валидацией коллизий в реальном времени.

## 5. Чеклист для ревью перед Шагом 5

1. **Типизация:** строгая типизация интерфейсов `SchoolSettings`, `Subject`, `Classroom`, `Teacher` в `types.ts` без `any`.
2. **Изоляция компонентов:** переиспользование компонента `TimeGridPicker` всеми справочниками с автоматической адаптацией под размеры недели.
3. **Валидация данных:** встроенная защита от дубликатов названий и некорректных числовых значений (вместимость, норма часов).
4. **Адаптивность UI:** строгая табличная сетка `min-w-[760px]` с защитой от вылета колонок действий на любых разрешениях экрана.
